# GTM Plan

## Overview

Turn a product (idea, existing PRD, or shipped v1) into a full go-to-market
plan: positioning, ranked channels, a pricing approach, and a phased launch
sequence with milestones. This is deeper than the lite GTM section inside
`prd-builder` — use this when the user needs an actual plan to execute
against, not just a one-paragraph angle.

**Announce at start:** "I'm using the gtm-plan skill to build your go-to-market plan."

## Process Flow

1. **Gather context.** If the user has an existing PRD (check `docs/prd/` in
   their project first), read it and reuse its target user, positioning, and
   any GTM-lite section rather than re-asking. Otherwise ask for the product
   and target user directly, one open question.
2. **Clarifying questions.** Ask one at a time. Cover: budget/team size for
   GTM execution, whether this is paid or free/freemium, any existing
   audience or channel already in hand (an email list, a community, a prior
   product), and target launch timeframe.
3. **Positioning.** One sentence: "[Product] helps [target market] [achieve
   outcome] by [mechanism]." Confirm it's specific enough to guide channel
   choice — a positioning statement that could describe five other products
   isn't done yet.
4. **Channels.** List 3-5 candidate channels (e.g. content/SEO, community,
   outbound, paid ads, partnerships, product-led/viral). Rank them by fit for
   this specific target market and budget — don't default to a generic list;
   justify the ranking against who the early adopter actually is and where
   they already pay attention.
5. **Pricing approach.** Recommend a model (free, freemium, flat subscription,
   usage-based, one-time) with reasoning tied to the target user's buying
   pattern, not a generic recommendation. Include a rough anchor price/tier
   if the user has enough signal to name one; otherwise flag it as an open
   question rather than inventing a number.
6. **Launch sequence.** 3-4 phases (e.g. private beta → waitlist → public
   launch → post-launch iteration), each with what happens, a rough
   timeframe, and one exit criterion that says when to move to the next phase.
7. **Write the doc** to `docs/gtm/YYYY-MM-DD-<project-slug>-gtm-plan.md` in
   the user's project (create `docs/gtm/` if it doesn't exist).
8. **Self-review.** Check positioning and channels agree on who the target
   user is, pricing matches the positioning's value claim, and every launch
   phase has a real exit criterion (not "when it feels ready").
9. **User review gate.** Point the user to the file, ask them to review
   before treating the plan as final. Wait for their response.

> Generated by the gtm-plan skill on <date>. Review and edit before treating this as final.
