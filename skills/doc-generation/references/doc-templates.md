# Doc Generation — Templates

Each template below is generated from the same source PRD (see `SKILL.md`
step 1). Every generated file starts with a one-line backlink:

```markdown
> Generated by the doc-generation skill on <date> from `docs/prd/<source-prd-filename>`.
```

## Backlog

**Source mapping:** one backlog item per user story in the PRD, grouped by
the PRD's MVP scope (Now/Next/Later).

**Path:** `docs/backlog/YYYY-MM-DD-<project-slug>-backlog.md`

```markdown
# <Project Name> — Backlog

## Now
- [ ] <item derived from a Now-scoped user story> — <one-line acceptance note>

## Next
- [ ] <item derived from a Next-scoped user story>

## Later
- [ ] <item derived from a Later-scoped user story>
```

## API Contract Sketch

**Source mapping:** one resource per core entity in the PRD's Data &
Architecture section; endpoints inferred from the user stories that act on
that entity.

**Path:** `docs/api/YYYY-MM-DD-<project-slug>-api-contract.md`

```markdown
# <Project Name> — API Contract Sketch

> Sketch only — not a full OpenAPI spec. Confirm before implementing.

## <Entity Name>

- `GET /<resource>` — <what it returns, tied to a user story>
- `POST /<resource>` — <what it creates, tied to a user story>
- ...

(repeat per core entity)
```

## Onboarding Doc

**Source mapping:** summary + target user from the PRD, MVP scope for
"what exists today," open questions section flagged as "still evolving."

**Path:** `docs/onboarding/YYYY-MM-DD-<project-slug>-onboarding.md`

```markdown
# <Project Name> — Onboarding

## What this is
<PRD summary, restated for a new team member>

## Who it's for
<PRD target user>

## What exists today (v1 scope)
<PRD's Now scope>

## What's still evolving
<PRD's open questions>

## Where to go deeper
<link back to the source PRD, and to backlog/API contract sketch if generated>
```
